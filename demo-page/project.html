PROJECT DEEP DIVE

How the Kickoff Agent transforms your product lifecycle.

An in-depth look at the architecture, workflow, and engineering decisions behind the Zalo Product Kickoff Agent.

1. The Context Switching Problem

In modern product development, information is highly fragmented. Product Managers write requirements in Docs. Designers create visuals in Figma. Developers track tasks in Jira. When it's time to "kick off" a sprint, ensuring all these platforms are perfectly synchronized is a manual, error-prone nightmare.

2. The Spatial Agent Solution

Instead of building another chatbot sidebar, we built a Spatial Canvas. Using `tldraw`, you interact with AI agents visually. You drop a Figma link onto the canvas, ask the agent to extract the UI components, and the agent visually maps out the Jira tickets right in front of you.

Show agents drawing on the tldraw canvas

3. Secure, Local-First Execution

Enterprise data is sensitive. The Kickoff Agent operates as a local Electron desktop application. We use a Local SQLite Outbox pattern for all state management.

When the agent proposes creating 15 Jira tickets, it doesn't just fire API calls blindly. It prepares the payloads and pauses for Human Approval. You review the immutable Payload Hash, click "Approve", and only then does the data leave your machine.

[ DEMO: APPROVAL WORKFLOW ]
Show the SQLite Outbox UI and Approval button

4. Figma MCP Integration

Our custom Figma Model Context Protocol (MCP) server bridges the gap between raw pixel data and semantic meaning. The agent doesn't just "look at an image" – it deeply inspects the Figma node tree to understand the design system tokens, text styles, and layout structures to generate pixel-perfect specifications.
